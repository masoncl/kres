# JSON producers, consumers, and invariants

This document is the source of truth for JSON boundaries in kres. It separates
model-authored control data from configuration, persistence, protocol payloads,
and human-facing prose. A parser is not allowed to infer which contract applies:
the call site selects one contract and uses its single acceptance path.

## Global invariants

| ID | Invariant |
|---|---|
| J1 | A model response declared as JSON is exactly one complete JSON value and the deserializer must reach EOF. Before inference repair, Rust may remove exactly one ` ```json … ``` ` or ` ``` … ``` ` wrapper only when it encloses the entire trimmed response; the body then passes through the identical strict contract. No surrounding prose, second value, embedded JSON string, candidate selection, or brace extraction is accepted. |
| J2 | Every model JSON boundary has one named serde DTO or one workflow-owned JSON Schema. Unknown fields are rejected at every typed nesting level. |
| J3 | Control fields are required unless omission has an explicit semantic meaning. `#[serde(default)]` must not turn a required decision into a silent false, empty string, or empty list. |
| J4 | A shared code-agent envelope must contain at least one shared field or explicitly allowed workflow extension. `{}` is not a response. Workflow-required outputs are checked separately after projection. |
| J5 | JSON Schema used in repair prompts is generated by `schemars` from the accepting DTO. Dynamic workflow outputs use ordinary JSON Schema from the workflow file. No handwritten pseudo-schema or shorthand compiler exists. |
| J6 | Repair is one additional model call containing the untouched rejected response, accepting schema, and exact validation errors. Each failure class has one owner: an invalid envelope gets whole-response repair; a valid envelope with malformed collection entries gets per-entry repair. The replacement goes through the identical accepting contract. Rust does not guess semantic equivalence from malformed prose. |
| J7 | A collection repair cannot silently change collection cardinality or association. Repair collections entry-by-entry, or constrain each entry with structural identity (`const`) and account explicitly for every rejected item. |
| J8 | Invalid structured output never triggers tools, todo/goal mutation, findings mutation, or filesystem changes. Deterministic fallbacks must consume already-valid upstream typed data, not malformed prose. |
| J9 | `code_output` and `code_edits` form one mutation batch. Resolve paths, validate content, apply edits in memory, and stage every final file before the first target replacement. Rollback uses the same atomic replacement primitive and reports every failure. |
| J10 | Diagnostic parsing APIs cannot be mistaken for acceptance APIs. Forgiving/raw preservation helpers are private and named as diagnostics; public consumers receive `Result<T, ContractError>`. |
| J11 | XML-framed main-agent actions are a distinct protocol: JSON is allowed only inside one `<actions>` array or one `<action>` object. The action DTO and tool-specific argument DTO validate before dispatch. No tag means gathering is complete; an invalid tag is a retryable protocol error and can never be represented as an empty action list. Surrounding prose is display-only. |
| J12 | Configuration and persistence JSON are not model repair candidates. They deserialize once into versioned/typed structures and fail or use an explicitly documented deterministic fallback. |

## Model-produced JSON boundary matrix

| Boundary | Producer call | Framing and accepting contract | Required data | Consumer / side effects | Failure and repair | Enforcement / tests |
|---|---|---|---|---|---|---|
| Fast gather | `pipeline.rs` fast gather and lensed fast gather | Exact object; shared code response plus gather semantic validator | `analysis` or a gather/control action; typed `followups`; `ready_for_slow` | Dispatches typed fetch requests | One generic repair, then fail task | `validate_fast_gather_text`; response contract tests; gather validation tests |
| Slow synthesis | `pipeline.rs::run_once_with_ctx` | Exact shared code response with workflow extensions | At least one envelope/extension field; mode-specific findings or code changes validated by caller | Produces task summary, findings, followups, edits | Envelope defects get one generic repair; malformed Finding records are repaired independently in place | `CodeResponseContract`; synthesis tests |
| Review lens | `pipeline.rs::run_lens` / shared fanout | Exact shared code response; workflow lens extensions when declared | At least one lens output field; workflow lens schema | Feeds consolidation only | Structural defects get representation repair; semantic failures rerun only the failing `(lens, model)` calls | generic/workflow lens validators and fanout tests |
| Lens consolidator | `consolidate.rs` | Exact shared response plus `comparison` / `comparison_details` extensions | At least one accepted field | Produces deterministic consolidated task | One generic repair; on failure deterministic union of valid lens DTOs | consolidator contract/fallback tests |

Human-facing `/summary`, model smoke-test output, and ordinary main-agent prose are
not JSON contracts. They must not be routed through JSON repair.

## Rust-produced JSON consumed by models

All model requests are produced with `serde_json::to_string` or
`to_string_pretty`; interpolation may insert serialized JSON values but must not
construct a JSON envelope by string concatenation. Important producers are:

- pipeline gather/synthesis/lens request structs;
- goal, plan, and goal-check request structs;
- todo reconciliation request;
- consolidator and promoter request structs;
- workflow prompt context and output-schema tail;
- generic repair request;
- `/compact` request.

Serialization failure aborts the call. Requests are never token-shrunk. Exact
deduplication happens on typed values, and naturally partitionable inputs retain
every byte across their serialized parts.

## Configuration JSON

| Data | Producer | Consumer | Invariant |
|---|---|---|---|
| Model provider files | operator / `setup.sh` | `kres-agents/src/config.rs` | Strict typed provider/model selection; unknown fields fail. Multiple-model files require explicit disambiguation. |
| `settings.json` | operator / setup | `kres-repl` / CLI | Typed settings; malformed settings produce an explicit startup error or documented default behavior. |
| Workflow files | shipped config / operator override | `workflow.rs` | JSON parses, validates against embedded workflow schema, and deserializes with denied unknown fields where applicable. Output `schema` is standard JSON Schema only. |
| MCP registry | setup/operator | MCP startup | Typed server definitions; malformed entries do not start a server. |

Configuration parsing never calls an LLM and never uses brace recovery.

## Persistence and protocol JSON

| Data | Producer | Consumer | Invariant |
|---|---|---|---|
| `findings.json` | `jsondb` / findings store | resume, report, summary | Versioned canonical Finding schema; atomic jsondb write; unknown Finding fields rejected. |
| `session.json` | task manager/reaper | `--resume` | Versioned typed session snapshot; atomic temp+fsync+rename; in-progress state normalized on load. |
| `workflow-<id>.json` | workflow executor | workflow resume | `schema_version` checked before typed deserialization; incompatible snapshots ignored explicitly. |
| `code.jsonl`, `main.jsonl` | turn logger | humans/tools | One serialized `LogEntry` per line; logging failure does not alter workflow control state. |
| LLM HTTP JSON/SSE | provider / gateway | `kres-llm` | Provider-specific typed envelope; protocol errors are transport failures, not model JSON repair candidates. |
| MCP JSON-RPC | kres / MCP server | `kres-mcp` | JSON-RPC id correlation and typed result/error envelopes; tool payload validated before dispatch. |

## Enforcement map

- J1/J2/J4/J5: `kres-agents/src/response.rs` (`CodeResponseContract`) and
  `kres-agents/src/json_repair.rs` (`parse_strict_json`). The latter first
  rejects duplicate keys recursively, then attempts raw path-aware
  deserialization plus `Deserializer::end()`, and may
  retry that exact operation after removing one whole-response Markdown fence.
- J3: required serde fields in `goal.rs`, `todo_agent.rs`, workflow judge,
  review ledger, and `/compact`; boundary tests reject `{}` and partial DTOs.
- J6: `json_repair.rs::repair_json_response`; callers preserve the original
  structured validation errors and deserialize returned text through their
  original DTO/contract. Consolidation separates envelope repair from
  per-Finding repair so the same failure never enters both paths.
- J7: `finding_repair.rs::FindingRepairResponse` uses `[Finding; 1]`, processes
  rejected records independently, and checks stable ids.
- J8/J9: `workflow_runner.rs` stages code changes without writing and validates
  model and machine-derived outputs against that staged view. `workflow_exec.rs`
  owns the final accept/discard decision and commits only after eval passes.
  Ledger state and exact accepted effects are snapshotted before mutation; the
  unused post-action engine was removed in favor of explicit reaper steps. File
  commits use bound directory descriptors, reject dangling target symlinks,
  and cannot be redirected by parent-path replacement. Reaper artifact actions
  are persisted before dispatch and replay desired state after interruption;
  failed git commits restore the exact pre-action index while `HEAD` is unchanged.
- J10: `diagnose_code_response` is explicitly diagnostic and is not exported at
  the crate root; production consumers validate before acting.
- J11: `main_agent.rs::parse_actions` returns `Ok(empty)` only when there is no
  action tag and `Err` for malformed framed actions. The fetch loop feeds that
  error back to the main agent without dispatching the batch.
- J12: strict model/settings/workflow parsing and explicit session/workflow
  snapshot versions; none invoke model repair.
